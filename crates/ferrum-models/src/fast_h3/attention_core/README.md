# Composed VSA attention core

`FastH3AttentionCoreSource::prepare` consumes the original transformer package, a block index, a checked tile layout, independent batch count, explicit dense/trained region selection, prefix arithmetic and capacity limits. Its seven input IDs are exactly the outputs of `FastH3AttentionInputFamily`: tiled Q/K/V, packed raw gate and F32 pooled Q/K/V. The final output is BF16 `[batch * packed_rows, hidden]` after the original `attn.to_out` NVFP4 projection. It can feed the existing residual/norm2 and FFN consumers without a Host tensor bridge.

One Core program computes scaled pooled scores once. The same value feeds softmax/PV and native region selection. Prefix attention centers all padded K rows once and exports that original BF16 centered K to Sage quantization; only the prefix dense branch applies the per-head FP8 roundtrip. The video Q suffix retains its padding slots. Sage quantization produces six physical tensors, and dynamic sparse attention consumes them with the shared scores and an explicitly bound checked region owner.

The video head-axis permutation is bit preserving. Prefix and video results are concatenated separately within each batch, then the checked Untile map restores packed order. Compression uses one F32-to-BF16 head permutation and the checked tile-value Expand map. The original raw packed gate enters the existing FMA operation before unit-scale NVFP4 activation quantization and the original output weight/scale/authoritative-alpha operands. No clamping or P-H3 image path is substituted.

Stored maps and scalars retain their original charged Host owners; original packed values and scales keep their full quantization encoding and physical-component roles. Preparation returns `Arc<CheckedVsaRegions>` separately. A digest in serialized configuration cannot grant authority to native device metadata: the caller must bind that exact checked owner to the existing native provider. Region payloads use the existing TransferStaging account and are retained through the existing prepared-operation/command lifecycle. The complete core adds no executor, allocator or device-memory ledger.

`ReferenceSequential` and `VendorFused` distinguish prefix arithmetic. The complete graph still requires the actual Sage and NVFP4 providers; the sequential-prefix profile is useful for contract inspection and is not an implemented all-Reference execution path. CUDA uses the vendor profile and the existing explicitly configured cuDNN loader, cache and workspace bounds. Unsupported providers, geometry and budgets fail without changing arithmetic profiles.

CPU tests validate every actual operation binding, shared dataflow, original Stored source roles, source identity and partial-admission rollback. The CUDA test additionally composes all branches in one retained session with two executions and one static upload per physical component. Its independent oracle is deliberately limited to zero Q/K and signed constant valid V per head/batch, raw gates -2/0/1 and a decoded dyadic output projection. The declared final tolerance is two BF16 ULP. This does not establish general attention error, reference tie-order equality, whole-model output quality, or performance.
