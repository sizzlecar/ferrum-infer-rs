## 2. 原目标、公式与不可悄悄改变的范围

工程目标是在保持模型质量、完整输出与资源安全的前提下，最大化满足 TTFT、TPOT、客户端可见 ITL SLO 的成功输出吞吐。容量公式沿用 [算法设计](slo-algorithm-design.zh.md)，用纯文本避免公式渲染失败：

```text
C*(W, theta) = sup over pi in CompleteRequestsPolicies of sup {
    lambda :
    P_lambda,pi(TTFT <= T1) >= p1,
    P_lambda,pi(TPOT <= T2) >= p2,
    P_lambda,pi(ITL  <= T3) >= p3,
    SuccessRate_lambda,pi >= p4,
    queue is stable
}
```

`lambda` 是请求到达率，`pi` 是使用当时可得信息、遵守资源与完整输出合同的策略；`theta` 固定模型质量、硬件与资源，`W_lambda` 固定到达和长度分布族。实际成功输出 tokens/s 是另一项实测量。有限测试不能证明全局最优或无限时间队列稳定，三项边际分位达标也不能替代请求级联合达标。

产品闭环必须在正常 `ferrum run`、`ferrum serve` 中自动完成：

```text
空成本状态 → 有界准备/真实 prefix capture-restore
→ 完整选源和工作预约 → 独立 Fitting / Residual / Qualification
→ 有效成本快照发布、更新、过期及漂移反馈
→ 普通请求执行前预测 → Enforce 实际选用与提交
→ issued / actual 正确配对 → 完整输出及资源退役
```

用户不应手工训练、导入成本文件或组合隐藏环境变量才能使用。成本 Unknown、规划失败或预测失约不能自动截短、取消正常请求或永久等待。正常用户行为应有 typed defaults、CLI/config 或文档化 preset。

保留原 **2ms** 规划预算、**120s / 2048 请求 / 16384 波**自动校准预算、**32,000,000** geometry visits 与各自原有内存账；CUDA 观测模板账的 32MiB 是另一项边界，不能混同。保持 F/R/Q 独立、原数值资格与真实容量校验。不得提高默认预算、删除慢样本、降低资格门、复用 Fit 样本充当 Qualification、裁剪输出或退款已消费工作来制造通过。

## 6. 下一步方案：先证明，再修改

**第一优先：完整选源义务和总预算。** 以G29已成功的精确host/product/readback/route/数值支持为基线，把G32实际输出逐项对应到选源、独立资格、安装和普通预测。保留Full width3与五host/two-product等原支撑，不能用“全局算法U包含某项”替代。冻结每个class frontier的代码存在，但本轮未证明它在CUDA进入并解决该义务；缺失的拒绝原因需要在已有Rust计划/选择路径定位，不能猜一个条件再重跑整套。

**第二优先：让有限计划的实际构造和同时驻留内存一致。** 当前候选190份全局occurrence上限造成Metal授权失败。只读审计得到一个局部严格结论：

```text
occurrences <= min(global_remaining_requests, finite.requests)
            <= min(global_remaining_requests, 同一完整候选/scope的periodic.requests)
```

生产唯一新建入口先构造同scope periodic，只有finite三账非增才接受，且每occurrence至少一个请求。因此可同时收紧该候选的 `build_with_view` 与 `storage_bound`，不会删掉原可接受的单候选计划。这里builder的global cap约束occurrence数；未admitted候选的完整请求费用仍可能超过global，最后的请求admission不能省略。
