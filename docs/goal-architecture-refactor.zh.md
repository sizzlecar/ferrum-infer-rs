# Goal：统一执行架构，为 SLO 优化建立可靠基础

**状态：目标已激活，R0 实施中。** 工作分支：`refactor/execution-architecture-20261018`，从 2026-10-18 的干净 `main`（`c2be4c67`）开始。首个 checkpoint 退役独立 embedding/ASR/TTS 链路；原工作区未合并的旧 SLO 实现不作为代码基底。

R0 两批退役清理及 LoRA 隔离修复已合并（PR #429–#431），必需 CI 全过；保留链路通过真实 CPU `run` / `serve`、Metal 定向检查及 CUDA 图重放后的 LoRA 数值回归。当前统一来源绑定：冻结配置、执行器实际来源报告、启动前校验，以及 legacy 加载器的语义/物理配置一致性。原始证据留在仓库外交接目录，没有新增性能或 SLO 达标声明。

## 1. 目标与第一原则

把 Ferrum 收敛为一套边界清晰、资源与状态有明确所有者、能够持续优化的推理架构。保住本轮明确保留的文本生成能力和默认性能，退役缺少可靠验证的非核心旧功能，使下一版 SLO 的调度、估计与校准能够独立演进。

**正确性、性能、良好架构是第一原则；最小改动不是原则。** 必要时重写接口、拆分 crate、迁移调用方并删除旧实现。分阶段合并用于控制迁移风险，不用于永久保留错误抽象。仅搬文件、包一层适配器或减少代码行数，不算完成。

- 正确性包括数值与输出语义、提交与取消语义、资源生命周期、缓存一致性；协议返回成功不足以证明正确。
- 性能以默认配置下的完整推理链路衡量；避免为抽象引入每算子动态分派、重复复制、分配或同步。保留可验证的专用快路径。
- 架构以职责、所有权和依赖方向衡量；不按文件行数、trait 数量或版本号数量验收。
- 不以静默丢功能制造“统一”，也不为历史支持声明保留没有可靠验证的实现。按用户授权明确划分保留与退役范围；内部 API 可以调整，产品退役同步清理入口与支持声明。

本 goal 交付可运行、可验证的 **SLO 扩展基础与最小闭环**。全工作负载的吞吐—延迟联合优化属于后续性能 goal；本次不能以接口存在宣称 SLO 达标，也不能以暂未达标无限延长架构重构。

### 范围收敛：先退役低验证的旧功能

用户已授权删除 BERT、TTS、ASR 等未严格验证的旧功能，仅保留必要扩展点。**它们不再计入统一执行协议的迁移分母，也不以先补齐模型质量测试作为删除前置。** 当前有局部单测与协议 stub；TTS 还有默认忽略、缺权重可跳过的真实权重 smoke，不能因此描述为“完全没有测试”，也不能当作持续的产品质量验收。

| 旧投机解码入口与专用状态机 | 退役仅 legacy 接入、缺少真实模型验收的实验链路 | 不为 mock 测试保留平行驱动；将来通过统一的实际执行/提交契约扩展 |
| 旧 whole-prompt prefix 复用 | 退役只克隆 handle 身份、缺少实际 KV fork 的复用；保留 typed checkpoint/restore | 默认关闭不等于正确；未支持 provider 明确拒绝，不泛称所有路径具备 prefix 能力 |

退役要贯穿实现、loader/registry、CLI/HTTP 入口、独占配置/依赖、示例、CI smoke 与支持文档；删除只服务于退役实现的测试，保留或改写仍有价值的协议/共用组件测试。失效模型类型或任务必须明确拒绝，不隐式转到文本生成、空输出或 stub。不得只隐藏帮助或关闭 feature 后留下整套旧状态机。

仓内未找到调用方不能证明公开 API 无外部使用。清退这些旧 API 时明确破坏性变化或受支持替代入口；Qwen3-MoE 还须统一语义来源与权重目录配置的身份/架构判断，不能只修一处 GGUF 分流就认定全部入口已关闭。退役旧构造器不删除通用 custom executor 扩展能力，有效的缓存/释放/回退测试迁至保留路径。现有 layer-split 接线属于保护范围，代码存在本身不构成多 GPU 性能或正确性验收。

来源 API 迁移：移除 `LlmExecutor::new_with_vnext_model`、`vnext_model`、`vnext_family` 的未接线计划标签；实际使用产品来源的 legacy 构造器改用 `new_with_model_sources`，保留无来源的 `new`。配置了产品来源的自定义 executor 须通过 `bound_resolved_sources` 报告其实际来源；typed 实现还校验真实 plan。此报告是可信实现的组装一致性合同，不是执行授权或全部文件的原子快照。

扩展点限于任务能力声明、可组合的注册/装配边界，以及未来按任务定义独立请求/结果的空间；**不新建无人使用的 Embed/ASR/TTS 引擎、空实现或插件框架来替代删除。** Candle、量化加载、通用算子等仍被文本 LLM 使用的依赖继续保留；独立 CLIP 处理链和未支持的聊天视觉输入不是同一件事，不能删掉主线已有的能力限制校验。

## 3. 目标架构与依赖边界

| 层 / 目标位置 | 拥有的职责 | 不应承担的职责 |
|---|---|---|
| `ferrum-types` | 通用值类型、配置声明、能力与数值描述 | 自动调优策略、运行时全局变量、SLO 拟合逻辑 |
| `ferrum-interfaces` | 不依赖执行实现的基础端口与公共语义，例如 tokenizer、sampler、模型描述 | 资源池实现、具体 runtime 授权、产品默认选择 |
| `ferrum-runtime`（拟新增） | 计划准备、资源授权、提交/完成/退休、设备执行端口、复用与失效、实例上下文 | 请求 SLO 目标、统计特征、模型名称策略 |
| `ferrum-execution`（拟新增） | 建立在 runtime 授权之上的产品执行契约、泛型执行驱动、结果/延期/取消协议；契约与驱动分模块 | 第二套资源运行时、具体模型/后端装配、训练器、HTTP 协议 |
| `ferrum-models` / `ferrum-kernels` | 模型语义与计划生成；CPU/Metal/CUDA 的具体执行、布局和数值能力 | 校准样本目录、训练 schema、SLO 拒单策略 |
| `ferrum-engine` | 请求生命周期协调、采样、执行事务、输出额度与取消 | 重复的物理资源账本、训练器、HTTP 协议拼装 |
| `ferrum-scheduler` | 队列、批组成、资源/时间准入策略；成本估计的消费接口 | KV/graph 的直接所有权、输出传输、后台模型发布状态机 |
| 原 `ferrum-kv` | 退出 Engine 的生产资源记账；必要凭证/统计类型迁入对应所有者 | 与模型物理 KV 并行的容量账本；遗留测试依赖在退役前迁移 |
| SLO 估计/校准组件 | 从执行事实提取特征、训练、评估、发布不可变快照 | 在每次前向中要求模型或 kernel 构造统计 schema |
| 产品装配层与 `ferrum-server` | 统一配置解析、能力选择；HTTP/SSE 协议与传输 | 另起一套执行与缓存状态机 |
| benchmark / devtools | 工作负载驱动、客户端测量、profile 存档、发布检查 | 成为生产 kernels/runtime 的普通依赖 |

依赖方向（箭头指向被依赖者）：`engine → scheduler → execution → runtime → interfaces → types`，Engine 也直接消费 execution；execution 不反向依赖 scheduler。kernels 实现 runtime 的设备端口，models 提供语义/权重和合法执行实现；execution/runtime 不反向依赖 models 或具体 kernels。基础 interfaces 不重导出依赖自己的上层 crate。SLO 组件消费只读执行事实，发布策略快照；数据面不反向依赖 SLO 实现。新 crate 名称可在 R1 调整，但上述责任和依赖关系必须落地，同时更新 workspace membership 和发布依赖顺序。

产品装配层组合模型准备结果、具体设备 runtime 与泛型驱动。迁移 `VNextModelExecutor<R>` 时同时解开其对 `PreparedProductionModel` 的依赖，将中立准备输入与编译结果归到正确层，并保留 source/registry/初始化身份校验；不能整文件搬迁后让 execution 再引用 models。泛型驱动本身已后端中立，不能将这项整理描述成新消除的具体 GPU 绑定。量化格式描述/解析与设备执行也按此分层，不能经 quantization 引回 kernels 依赖环。

legacy Engine 的容量分配记录与模型自己的物理 KV 当前是两套账本，不等于已证明重复分配两份 GPU KV。统一后容量权威归执行 runtime，Engine/scheduler 只消费凭证与只读状态。`ferrum-kv` 的 testkit 使用和公共统计类型需迁移；没有剩余独立职责后删除 crate，不为维持旧测试保留生产双重记账。

公共契约的具体归属按依赖闭包决定。`PrefixRestoreObservation` 等当前借用带授权语义的 deferral，不能因名称像数据就下沉到 `types`：拆开只读观测表示与可操作的授权，或将完整授权契约放在正确边界；不得把私有字段/构造校验改成任意可伪造的快照来解环。

模块整理同时覆盖 `vnext_executor`、`continuous_engine`、scheduler `continuous`、`axum_server` 和模型计划构建文件。以装配、状态转换、后端执行、采样/文本投影、协议传输、观测分别成模块；测试随责任归属。去掉完成迁移后的 `vnext` 过渡命名、失实注释与旧导出，不做仅改名的重构。

## 4. 必须建立的执行契约

### 4.1 一个执行协议，旧路径有终点

构建时根据声明能力选择执行实现。Engine 的 batch/prefill/decode 主循环只面对统一协议，不持续判断资源属于 legacy 还是 PlanRuntime。CLI、`run`、`serve` 与公共 EngineBuilder 使用相同的来源解析和能力规则。

迁移期间允许兼容 adapter，但它必须实现统一的提交、完成、取消和容量协议；旧算法可暂时留在 adapter 内，不能再维护平行的 Engine 调度/资源所有权。每个保留能力记录迁移去向与退出里程碑；退役项按 §1 删除。存在尚未覆盖的保留能力时，不能宣告旧架构退出完成。最终模型实现可以复用旧算子，但不再依赖两套执行协议之间的转换 adapter。

**统一控制流与资源合同，不要求全部模型改写为同一种静态算子图。** 保留的模型可以直接实现新契约并继续使用合法的内部算法/tensor；不能每步套一层旧 `PrefillInput` / `DecodeInput` 的 Tensor 转换，再把旧路径包装成迁移完成。产品边界直接表达 token、位置、采样返回策略、资源凭证和实际结果，移除冗余复制；必要的设备上传/读取不以“零拷贝”口号一概禁止。非文本任务退役后不再为满足 causal trait 提供假的 prefill/decode。

最终删除旧的 Engine 分流、重复 KV 管理入口、失效 loader 分支和公开执行 trait 中仅服务旧控制流的方法。调试 whole-prompt cache 必须有真实 KV fork/checkpoint 语义，否则移除；不能用仅更换 cache ID 的 clone 跳过 prefill。

### 4.2 一次执行与一次逻辑提交

显式区分 `NotSubmitted → Submitted → DeviceTerminal → ModelCommitted`，再区分输出已排队、传输已发送和客户端已看见。设备完成不等于 token 已提交，服务器发送不等于客户端可见。批次保存每个参与者的实际进度与失败阶段。

- 仅确认 `NotSubmitted` 的工作允许执行回退；部分提交、KV 已推进或已有逻辑提交的工作不得整批重放。设备结果未知时进入受控隔离/失败路径。
- prefill、decode、mixed、prefix restore 使用同一套提交/取消原语；Engine、scheduler、executor 各保留其必要状态，不合成巨型共享状态表。
- 执行授权、容量、输出额度和唤醒各有唯一所有者；取消与 shutdown 回收已证明终态的资源。未知设备写入保持隔离，关闭可返回明确的失败/超时及未回收状态，不能误报释放成功。异步释放必须有明确排队、执行和等待机制，`Drop` 告警不能当作释放完成。
- 单实例只有一个登记并可等待的驱动；显式启动、惰性启动、重复启动、取消与关闭遵守同一生命周期。

### 4.3 计划、绑定、授权与拓扑分开

稳定的算子图、权重和布局可复用；请求参与者、位置、实际工作范围、当前 lease 与提交授权按需要更新。地址相同不代表授权相同，epoch 只对其声明覆盖的变更有效。

资源类型区分 **模型上限、服务配置、所需逻辑范围、已分配物理范围、当前活跃范围**。预算、绑定校验与执行消费一致的准备事实；不能为了补齐容量复制整行。数值契约区分权重量化、激活、KV、累加与输出精度。

resident/graph 缓存键及失效规则覆盖实例、设备、参与者/顺序、布局、native kernel 路径、分区拓扑和依赖代际；允许已有证明支持的增量刷新。覆盖 prefill/decode 转换、prefix 恢复、取消、容量变化和非稳态批宽，不能把客户端 C 当成实际物理 M。

CUDA graph、stream、工作区与可变配置归属于 runtime 实例。确需跨实例共享的设备容量服务有独立所有者、引用和隔离规则；加载/关闭一个模型不得重置另一个模型。静态不可变的能力/制品缓存可以共享。

### 4.4 输出与观测各有边界

输出从 Engine 到 HTTP/SSE 全链路有界，区分生成、待发、已交付游标及终态。慢消费者按公开策略暂停或取消自身请求，不无限积压或阻塞其他请求；满队列不得静默丢文本或提前推进交付水位。正常完成保证输出连续且不重复提交；取消/断连可停止剩余输出，但不得伪报正常完成，服务端不承诺跨网络的客户端恰好一次接收。

所有 tokenizer 解码和 stop/thinking/tool 投影均移出全局 sequences 写锁，包括需要全量重解码的正确性回退。锁内只做有界状态读取/快照与版本校验后的短提交；锁外结果遇取消或版本变化不能盲目发布。增量实现须证明上下文与字节边界正确，不能假设“四个 token 足够”；不支持安全增量的 tokenizer 保留明确的锁外正确路径，并测量成本。

执行不变量错误、设备错误与观测传输错误使用不同类型。可选 telemetry writer 失败可降级、计数并限流报告，保持执行事件游标有效；不能吞掉 mixed error 或让坏 sink 永久封死后续推理。显式要求 replay/verification 完整证据的任务可失败，但不能因此重放已执行工作。

关闭诊断时不构造 JSON、全队列快照或重型特征；开启后的采样、队列和内存有界。必需的轻量执行事实、客户端指标与可选详细 trace 分开；生产运行时不依赖发布工具。

## 5. 后续 SLO 的扩展合同

### 目标与口径

沿用 [README 的目标](../README.md)：固定硬件、模型、输出策略、请求集合/到达计划和测量窗口，在预先声明的 TTFT、TPOT、ITL 分位数上限及最低完成率约束下，最大化有效输出吞吐。

请求从入口携带单调时间锚点，覆盖排队与 tokenization；墙钟跳变不改变 deadline，跨边界传递不能悄悄重置请求年龄。跨进程只比较有明确定义的持续时间/关联事件，不直接相减不同时钟。保留生成、排队、服务端发送与客户端接收的不同时间。TTFT 以首个非空可见文本为准；主表 ITL 是相邻非空 SSE 文本事件间隔，单 token 诊断另列并披露传输合并。TPOT 的样本单位、分母和不足两个输出 token 的处理须声明。拒绝、失败、超时和未完成请求保留在固定 cohort 的完成率分母，不能通过拒单或删掉缺失样本制造达标。

### 数据面只提供执行事实

提供轻量 typed 执行摘要：请求/step 关联、实际提交与完成的参与者和工作量、实际批宽/形状、数值路线、资源占用、prefix 命中/恢复、resident 命中/重建/回退，以及分层时间和测量可信度。未知占用不是零；取消、截断、回退不能按原计划量记成已完成。合法冷路径和回退后的完成样本保留路径标签，不能一律过滤后只学习理想稳态。

CPU wall time、设备事件区间和包含重叠的耗时不得直接相加。区分准备/提交、设备完成、采样/文本后处理与输出等待；成本估计器明确它预测的是设备、执行服务步还是端到端延迟。不能一律删掉 Host 成本，也不能把慢客户端等待拟合成 GPU 成本。

### 控制面独立演进

- 资源准入提供真实容量与等待条件，时间准入消费成本预测和用户目标。两者由同一请求提交协议协调，不让 SLO 再复制资源账本、epoch 或唤醒状态。
- 执行摘要经有界、非阻塞通道进入独立估计/训练组件；丢样和覆盖偏差可观测，推理循环只读不可变快照。发布原子切换，声明适用域、不确定性、过期及未知路径策略；训练停顿不能阻塞执行，控制面关闭后不运行拟合、训练或对应序列化。
- 用正交能力与执行路径描述域：shape、数值路线、prefix/cache 状态、resident/cold/mixed 与硬件能力。新增统计特征应在估计层完成，不把 `route_population`、catalog 版本或训练 receipt 塞进 kernel/model 接口。
- wire/artifact 版本只用于真正的兼容性变化；内部保持一个规范表示，在边界升级/拒绝旧产物。保留必要兼容校验，但不因普通缓存命中率或并发变化使整个 profile 无理由失效。域外样本明确降级、补采样或限制准入，禁止静默当作可靠预测。
- 在声明支持的执行路径上，Prefix Cache、checkpoint 与自动校准可以共同工作；未支持的路径明确报告能力限制，本轮不要求为所有后端新增 checkpoint。成本模型表达恢复/命中/冷启动的差异。校准器通过受支持的 Engine/执行能力接口驱动工作负载，不在生产 Engine 嵌平行 CalibrationSession 状态机。
- 所有策略通过 typed 配置、默认值或文档化 preset 暴露；吞吐阶段已验证的默认优化保留。标准构建包含已声明能力，能解释 requested/source 与实际 selected；参考数值路径与显式配置优先级清晰，`run` / `serve` 一致。未支持的设备/形状/容量只走已声明的合法回退，ABI、初始化或执行错误不能伪装成普通资格不足，也不能暗中降低用户并发配置。

**本 goal 的 SLO 验收闭环：** 真实执行事实能够驱动一个参考估计器和时间准入策略；验证 prefix 开/关、混合工作、样本丢失、未知路径、快照替换及训练故障；证明它们不破坏资源/输出正确性。参考估计器可以简单，但不得把全局仿射模型对所有路径的准确性当作前提。具体阈值下的联合性能达标另行实测。

## 6. 里程碑与验证流程

| 阶段 | 交付 | 退出条件 |
|---|---|---|
| R0：范围、基线与合同 | 从干净主线建立工作分支；确定保留/退役清单并开始首批旧功能删除；整理状态图、依赖图、默认配置与性能基线 | 每项能力有明确去向，退役链路不再拖累迁移；先声明比较口径与回归预算 |
| R1：契约与运行时 | 解开共享契约依赖；分离 runtime；统一提交错误与实例上下文 | 无依赖环；授权不可伪造；真实 Plan 与后端组合通过；失败重试不重复执行 |
| R2：单一请求与输出链路 | 统一 driver/loader；完成事务、取消/回收、驱动管理、有界输出；隔离观测；单调时间与实际工作摘要 | 已迁移能力通过故障注入、慢消费者、流式语义和 run/serve 回归；未迁移的保留能力有明确去向 |
| R3：执行与策略收敛（与 R4 并行） | 完成剩余保留能力迁移；计划/动态授权、容量/活跃范围、拓扑失效；公共语义验证、typed 配置与模块分责 | 默认配置的完整链路无未解释退化；保留能力无缺口后，旧 Engine 分流、转换 adapter 和重复旧接口删除 |
| R4：SLO 接缝闭环（R2 后开始） | 在主力文本路径接入独立估计/发布与准入组合；校准与 prefix 共存，不等待全部旧模型迁移 | 更换估计器不改模型/kernel；故障与域外路径策略可测；口径与客户端证据一致 |
| R5：收尾合并 | 代表性后端/架构与性能验收，迁移文档、默认行为和代码合并 | 下列完成条件全部满足；未测项与遗留问题明确，无“先保留两套以后再删” |

阶段允许并行准备，依赖合同必须先确定。安全缺陷可先落地修复，不必等待全部搬迁；每个 PR 对应完整的架构责任或行为问题，大小由正确的边界决定。到可验证 checkpoint 就提交/push，不积攒长时间未提交改动；只提交必要文档，过程日志与数据放仓库外。

依赖顺序为 `R0 → R1 → R2 → {R3, R4} → R5`。尽早用四个真实组合切片否证设计：只读观测不能伪造执行授权；部分批失败/坏 sink 不重复执行或封死后续步骤；停读客户端下内存有界且其他请求保持进度；prefix 截断、恢复和 cold fallback 的实际工作量均可正确表示。慢客户端的延迟影响按预声明预算和噪声判断，不要求 P99 绝对不变；完整执行状态账本与可采样/丢样的估计通道分开，不要求生产训练采集 100% 波次。

候选选择和验证遵循以下顺序：

1. **先定位、再选候选。** 写清瓶颈证据、将消除的整段工作、预计上限、新增成本和风险。架构正确性修复可以没有吞吐收益，但不得伪装成性能提升；性能候选优先覆盖最大可消除成本。
2. **先定向正确性，再完整链路短测。** 从受影响单测/后端用例开始，尽快获得无重型仪器的同机 A/B。复用 Rust harness 与构建缓存；不设固定时限替代技术判断，每步交付可测切片或明确排除结论。构建/硬件阻塞单列报告，不用长时间无结果代替进展。
3. **先筛选、再扩大。** 先选最能否证假设的拓扑/并发；影响现有 CUDA 27B decode 的候选优先检查 C8/C32，再覆盖其他受影响档位。无收益或明显退化时停止性能候选并复盘。Metal 按实际批宽与尾批选择样本。微基准、上传字节数和调用数只解释原因，不代替端到端收益。
4. **稳定里程碑才完整验证。** 执行仓库要求的 fmt/check/test/clippy 与相关后端检查；共享推理变化验证 `run` 和 `serve`。编译通过、协议正确、语义正确、性能结果分别报告，不靠绿色 CI 混为一项。

正式比较固定硬件/驱动、权重与数值配置、服务容量、数据样本和输出策略。以 pinned ShareGPT 为主；吞吐、TTFT/TPOT/可见 ITL 的 P50/P99、峰值内存、错误、完成率、样本量与重复次数一起报告。重构回归预算在 R0 按需求与测量噪声预先冻结，不事后放宽；没有阈值或缺少延迟证据只能标为“未证明 SLO 达标”。历史八格吞吐结果不是新的重构基线测量。

本轮预设回归预算：同窗基线对照下，输出吞吐下降不超过 3%，各延迟 P50/P99 上升分别不超过 5%/10%，峰值设备内存上升不超过 5%；不得新增错误、输出差异或降低完成率。短测用于筛选，正式判断采用固定样本的重复 A/B；顺序效应或测量噪声足以改变结论时补测并保留不确定性，不据单次波动判定通过，也不临时放宽预算。这些是重构回归门槛，不替代工作负载的绝对 SLO。

纯执行重构在相同数值路径与物理批形状下核对完整 token、文本、采样/停止及 usage 语义；已有非确定性须单独界定。改变数值路径或批布局时增加对应质量与敏感性验证，不把协议零错当作质量通过，也不对每个无数值变化的候选重复全量质量题库。未知来源的输出差异、非法地址与资源异常出现时，先停止性能推进并解决正确性。

保留 27B GGUF/CT 的代表性端到端比较，建立“能力/拓扑 → 代表性用例”的映射，尤其覆盖历史 9B attention/分区失效域与 Metal 实际 M 的尾批。既有证据按模型、数值路线和适用域复用，不跨域借用。Metal 仅比较 llama.cpp；vLLM 仅在 CUDA 比较。5090 可用时手动验证，不重新配置为 runner；不能用其他显卡的结果冒充 5090 结论，也不能把缺失硬件测试标成通过。

- [x] BERT/独立 CLIP embedding、Whisper ASR、Qwen3-TTS 等退役链路的实现、注册、入口、独占依赖及支持声明已清理；共享 LLM 组件保留，未支持任务明确拒绝，扩展点不带空引擎或假实现。
- [ ] 一个执行协议、一个受管驱动和一致的构建规则；旧 Engine 控制流与重复资源所有权退出，保留能力全部有可验证实现。
- [ ] 提交后失败、部分完成、prefix restore、取消/shutdown 与资源回收有组合测试；不重复执行，已证明终态的授权正确回收，未知终态隔离且退出状态明确。
- [ ] 输出全链路有界；正常完成不静默丢失/重复提交文本，Unicode、stop、thinking/tool、慢消费者和中途断连正确；可选观测故障不推翻正常推理，必需证据/不变量失败仍被识别。

- [ ] 默认优化继续生效，内部控制参数 typed，`run` / `serve` 共享解析规则；有同机默认配置的吞吐、延迟、内存及质量回归证据，所有超预算退化已解决。
- [ ] SLO 参考闭环与 prefix 共存；训练、发布、未知域和观测降级有明确策略；客户端指标与内部预测各自可解释，没有宣称未测的 SLO 达标。
- [ ] 必要工作区与后端检查完成，相关修改合并主线；迁移说明和一页结果/决定保持简洁，详细原始证据留在仓库外。
