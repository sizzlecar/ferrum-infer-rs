# RTX 5090 热门文本模型的 Auto 性能验收

**验收结论：保留主干默认行为。** 同卡 4B Q4_K_M 在 C48 的实测最大驻留数从 32 增至 48，容量修复成立。27B GGUF 在原有 C8 和 C16 负载的两轮吞吐均低于主干，合并各档两轮后分别低 4.28% 和 3.21%。C16 合并后的首 token P99 从 1062.4 升至 1107.9 ms，每输出 token P99 从 37.08 升至 38.88 ms。候选未满足吞吐、尾延迟均不退化的合入条件。现有测量没有定位差异的原因。

检验新版 `ferrum serve` 在实际模型上选择的驻留容量，以及客户端在该配置下得到的吞吐和尾延迟。0.8B 用于重现容量边界，热门模型使用 README 已公布的独立工作负载。实现、容量账本和 0.8B 压力测试见[容量目标](goal-auto-serving-capacity.zh.md)。

## 测量条件

2026-11-21，独占 RTX 5090、32 GiB、WSL、驱动 610.88、CUDA 12.8.1。暂时关闭原有 FastVideo 服务。对照为主干 `0603698cf` 和候选 `5d72c31c5`，服务端均为 Rust 1.91 的 `release-tools` 构建，HTTP 客户端始终使用公开 v0.20.1 的 Rust `bench-serve`。模型、客户端、算子锁及二进制均可按证据目录核验。17:19 左右管理用 SSH 曾中断，17:23 恢复。基准客户端与服务都在 5090 本机，27B GGUF 新版在断连期间写完四轮。关闭已完成任务的空闲进程后，从 27B CT 主干继续原定顺序，保留全部已完成的报告。

每种权重在相同设备上分别启动旧、新两个 Auto，上下文上限和单轮执行的 token 预算均为 2048。README 的历史 Ferrum 测量固定了服务端容量，本次两个版本均采样可用显存并自行选择驻留数。C8/C16 表示客户端同时发出的请求数。输出吞吐按成功响应的 usage 输出 token 计算。TTFT 是从发出请求到首个可见文本的延迟，TPOT 为从首个到末个可见文本的时长除以（usage 输出 token 数 − 1），ITL 是相邻非空 SSE 文本事件之间的间隔。每轮分别计算三项 P99，一项超限即记该轮失败。精度、选样、样本数、EOS 和门限沿用相应的历史报告。

- 4B、9B、30B、35B 使用 seed 42、每轮 10 次预热和 64 个正式样本、每个并发 2 轮。按客户端 tokenizer 选取 4–1024 token 的输入和 128–256 token 的参考输出，按各条参考长度生成，关闭提前 EOS。普通门限为 TTFT 2000 ms、TPOT 50 ms、ITL 100 ms。4B Q4_K_M 另按 #514 的 TTFT 500 ms 复核。SafeTensors 的 BF16 描述来源权重，Ferrum 实际采用 F16 激活及 KV。[原始测量](performance-rtx5090-popular-models-20261101.md)
- GPT-OSS 使用原版 Harmony 模板、默认 medium、自然 EOS、上限 512 token。每个版本启动两次，每次 C8/C16 各测 32 个正式请求、2 个预热。第一个非空 reasoning 或 final 文本都计入 TTFT。除三项延迟目标外，每次启动还须达到历史门限 737.79 / 1286.78 output tok/s。与 11 月 2 日相比，模板的系统日期变为 11 月 21 日，34 条提示词各有 1 个 token 不同，逐条长度相同。[原始测量](performance-rtx5090-gpt-oss-20261102.md)
- 两种 27B 使用原始 35B tokenizer 选样，实际服务按 27B tokenizer 和模板处理。每轮 8 次预热和 200 个正式样本，每档 2 轮。输入筛选为 4–1024 token，参考输出至少 4 token，预留 32 个模板 token 后总长不超过 2048，按参考长度生成并关闭提前 EOS。保留较严的 TTFT 442.08 ms、TPOT 29.5956 ms、ITL 88.7867 ms 门限。历史报告把两轮的请求和 SSE 事件合并计算 P99，本文另给出该口径。[原始测量](performance-popular-models-p0.zh.md)

每次启动另发普通和流式算术请求，核对最终答案、停止原因、usage 和 SSE 终止事件。正式负载逐请求核对冻结的原始提示词、参考答案标识、长度和实际 usage，同时检查 HTTP 错误、拒绝、空输出与损坏的流。语义检查覆盖算术样例，整份 ShareGPT 只做协议与用量核验。

同一默认可用预算为 29,186,378,183 字节。4B 两种格式均达到搜索上界 256。9B BF16 经过 7 次候选编译选到 213，浅 decode 计划峰值为 29,164,566,800 字节。35B GPTQ 经过 9 次选到 114，计划峰值为 29,140,611,760 字节。这些模型选中的单轮 decode 宽度均为 32。35B 两版进程从启动到 HTTP 就绪各观测一次，主干 207 秒、新版 224 秒，包含了加载、编译和预热。表中 C8/C16 测的是相应客户端并发下的表现。容量边界另在 0.8B 上按相同形状核过计划和物理分配，并实测了 C31、C256。[实物对账与满载压力](goal-auto-serving-capacity.zh.md#预测和实物逐项核验)
